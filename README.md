# กระดานแข่งใบงาน WOM Sensor Kit for micro:bit

เว็บแอปสำหรับให้นักเรียนติ๊ก Checkpoint ของใบงานแบบสด และให้ครูเห็นความคืบหน้าของทุกทีมพร้อมกันบนหน้าจอเดียว

ครอบคลุมใบงาน 21 ใบ คือ Advanced Course บทที่ 4.1–4.12 (รหัส A1–A11) และ Creative Course บทที่ 5.1–5.10 (รหัส C1–C10)

---

## ความสามารถ

**ฝั่งนักเรียน** — ตั้งชื่อทีม ใส่ชื่อและถ่ายรูปสมาชิก 3 คน เลือกใบงาน อ่านเนื้อหาใบงานเต็ม ดูรูปชิ้นงานที่ต้องประกอบให้ได้ ติ๊กความคืบหน้าการประกอบทีละช่วง ติ๊ก Checkpoint จับเวลา พิมพ์ตอบคำถามท้ายใบงาน และกดปุ่มยกป้ายตรวจ ปุ่มยกป้ายจะกดไม่ได้จนกว่าจะติ๊ก Checkpoint ครบทั้ง 3 ข้อ

**รูปสมาชิก** — แตะวงกลมเพื่อถ่ายรูปหรือเลือกรูปจากเครื่อง เบราว์เซอร์จะครอบเป็นสี่เหลี่ยมจัตุรัสและย่อเหลือ 220 พิกเซลก่อนส่ง รูปหนึ่งใบจึงหนักราว 15 กิโลไบต์ ครูเห็นหน้าสมาชิกบนกระดานทีมทำให้จำทีมได้เร็วขึ้นตอนเดินตรวจ

**การประกอบชิ้นส่วน** — ทุกใบงานฝังภาพขั้นตอนการต่อครบทุกขั้นจากคู่มือ Assembly Steps ไว้ในหน้าเว็บแล้ว รวม 916 ภาพ นักเรียนกดถัดไปทีละขั้น เลื่อนแถบ หรือแตะรูปย่อด้านล่างเพื่อกระโดดไปขั้นไหนก็ได้ แตะที่รูปใหญ่เพื่อขยายเต็มจอและใช้ปุ่มลูกศรซ้ายขวาเลื่อนต่อได้ ไม่ต้องเปิดไฟล์ PDF แยกอีก

**หน้าคะแนนรวม** — แท็บที่สามที่ทุกคนเข้าดูได้ มีแท่นสามอันดับแรกพร้อมรูปสมาชิก ตารางอันดับเต็ม และตารางรายใบงานที่บอกว่าแต่ละทีมได้อันดับเท่าไหร่ในใบงานไหน มีปุ่มเต็มจอสำหรับฉายขึ้นโปรเจกเตอร์หน้าห้อง

**ฝั่งครู** — คิวรอตรวจเรียงตามเวลาที่นักเรียนกดปุ่ม กดผ่านแล้วระบบให้อันดับอัตโนมัติ กดไม่ผ่านแล้วทีมนั้นจะยกป้ายซ้ำไม่ได้ 2 นาทีตามกติกา มีกระดานรวมที่แสดงแต่ละทีมเป็นจอ LED 5×5 แบบ micro:bit จุดละหนึ่งใบงาน และมีตารางสรุปคะแนนที่ดาวน์โหลดเป็น CSV ได้

**การซิงก์** — ใช้ Server-Sent Events ทุกเครื่องได้รับข้อมูลใหม่ทันทีที่มีการเปลี่ยนแปลง ไม่ต้องรีเฟรช

## ขั้นตอน deploy บน Railway

### เตรียมโค้ดขึ้น GitHub

```bash
cd wom-board
git init
git add .
git commit -m "กระดานแข่งใบงาน WOM Sensor Kit"
git branch -M main
git remote add origin https://github.com/<ชื่อผู้ใช้>/<ชื่อ repo>.git
git push -u origin main
```

### สร้างโปรเจกต์บน Railway

1. เข้า [railway.app](https://railway.app) แล้วเลือก **New Project → Deploy from GitHub repo** ชี้ไปที่ repo ที่เพิ่ง push
2. Railway จะตรวจเจอ `package.json` และรัน `npm start` ให้เอง ไม่ต้องตั้ง build command
3. ไปที่แท็บ **Variables** แล้วเพิ่ม

   | ตัวแปร | ค่า | ทำอะไร |
   |---|---|---|
   | `TEACHER_PIN` | รหัสที่ตั้งเอง เช่น `4821` | กันไม่ให้นักเรียนเข้าแผงครูไปกดผ่านให้ตัวเอง |
   | `DATA_DIR` | `/data` | บอกให้เก็บข้อมูลไว้ใน Volume |

4. ไปที่แท็บ **Settings → Volumes** กด **Add Volume** แล้วตั้ง Mount path เป็น `/data`

   ขั้นตอนนี้สำคัญ ระบบไฟล์ของ Railway จะถูกล้างทุกครั้งที่ deploy ใหม่หรือ container รีสตาร์ต ถ้าไม่ผูก Volume ข้อมูลทีมและผลตรวจจะหายเมื่อ Railway รีสตาร์ตบริการ ซึ่งอาจเกิดกลางคาบเรียนได้

5. ไปที่ **Settings → Networking** กด **Generate Domain** จะได้ URL หน้าตาประมาณ `https://ชื่อโปรเจกต์.up.railway.app`

### ใช้ CLI แทนได้

```bash
npm i -g @railway/cli
railway login
railway init
railway volume add --mount-path /data
railway variables --set TEACHER_PIN=4821 --set DATA_DIR=/data
railway up
railway domain
```

## วิธีใช้ในห้องเรียน

1. ครูเปิด URL แล้วกดปุ่ม **ครู** ใส่รหัสที่ตั้งไว้ใน `TEACHER_PIN` (ใส่ครั้งเดียว เบราว์เซอร์จำให้)
2. ฉาย URL ขึ้นจอหรือทำเป็น QR code ให้นักเรียนสแกน
3. แต่ละทีมเปิดบนแท็บเล็ตหรือมือถือของตัวเอง ตั้งชื่อทีม แล้วเริ่มแข่งได้เลย
4. ท้ายคาบครูกด **ดาวน์โหลดเป็นไฟล์ CSV** เพื่อเอาคะแนนไปกรอกในสมุดประเมิน

### แยกห้องเรียน

ต่อท้าย URL ด้วย `?room=` แล้วตามด้วยชื่อห้อง เพื่อให้แต่ละห้องมีกระดานของตัวเองไม่ปนกัน

```
https://ชื่อโปรเจกต์.up.railway.app/?room=m301
https://ชื่อโปรเจกต์.up.railway.app/?room=m302
```

ครูและนักเรียนของห้องเดียวกันต้องใช้ลิงก์ที่มี `?room=` เหมือนกัน ถ้าไม่ใส่จะเข้าห้องกลางชื่อ `main`

## โครงสร้างไฟล์

```
server.js              เซิร์ฟเวอร์ Express, SSE, บันทึกข้อมูลลงไฟล์ JSON
public/index.html      โครงหน้าเว็บ
public/style.css       สไตล์ทั้งหมด
public/app.js          ตรรกะฝั่งเบราว์เซอร์
public/worksheets.js   เนื้อหาใบงานทั้ง 21 ใบ แก้ไขที่นี่ที่เดียว
public/models/         รูปชิ้นงานที่ประกอบเสร็จ ดึงมาจากคู่มือ Assembly Steps
public/steps/<รหัส>/   ภาพขั้นตอนการต่อทีละขั้น เรียงเป็น 001.jpg 002.jpg ไปเรื่อย ๆ
```

| ตัวแปร | ค่าเริ่มต้น | คำอธิบาย |

| `DATA_DIR` | `./data` | โฟลเดอร์เก็บ `board.json` |
| `TEACHER_PIN` | ว่าง | ถ้าเว้นว่าง ใครก็เข้าแผงครูได้ ควรตั้งเสมอเมื่อใช้งานจริง |

## ข้อจำกัดที่ควรรู้

- ข้อมูลเก็บเป็นไฟล์ JSON ไฟล์เดียว เหมาะกับระดับห้องเรียนถึงระดับโรงเรียน ไม่ได้ออกแบบมารองรับผู้ใช้พร้อมกันหลักพัน
- ไม่มีระบบล็อกอินรายบุคคล ทีมยืนยันตัวตนด้วยรหัสที่เก็บในเบราว์เซอร์ ถ้านักเรียนล้างข้อมูลเบราว์เซอร์จะต้องตั้งชื่อทีมใหม่ ข้อมูลเดิมยังอยู่บนกระดานแต่ทีมจะกลายเป็นทีมใหม่
- รหัสครูเป็นการกันแบบง่าย ๆ พอกันนักเรียนทั่วไป ไม่ใช่ระบบความปลอดภัยระดับสูง

## ที่มาของข้อมูลการประกอบ

เลขหน้าในคู่มือและรูปชิ้นงานสำเร็จ ดึงมาจากไฟล์ `WOM_Sensor_Kit_For_Microbit_Assembly_steps.pdf` ของ Yahboom โดยตรง เลขหน้าที่แสดงในแอปคือเลขหน้าที่พิมพ์อยู่มุมล่างของคู่มือ ไม่ใช่เลขหน้าของไฟล์ PDF ซึ่งจะมากกว่ากันอยู่ 2 หน้า

ภาพขั้นตอนในโฟลเดอร์ `public/steps/` เรนเดอร์มาจากคู่มือหน้าละหนึ่งภาพ ย่อกว้าง 760 พิกเซล รวมทั้งหมด 916 ภาพ กินพื้นที่ราว 18 เมกะไบต์ ถ้าอยากลดขนาด repo ให้เรนเดอร์ใหม่ที่ความกว้างน้อยลง แล้วแก้ค่า `n` ในฟิลด์ `asm` ให้ตรงกับจำนวนไฟล์

## รายการโมดูลในชุด

ชุดนี้มีโมดูลอิเล็กทรอนิกส์ 10 ตัว อย่างละหนึ่งตัว และเซอร์โวบล็อก 2 ตัว

RGB · Button · Rocker · Photosensitive · Temperature & humidity · Infrared · Human body infrared · Color recognition · Ultrasonic · Digital tube

ชุดนี้ไม่มีลำโพงหรือบัซเซอร์แยกต่างหาก ใบงานที่ต้องใช้เสียงจึงใช้ลำโพงในตัวของ micro:bit V2 และไม่มีโมดูลปุ่มตัวที่สอง ใบงานที่ต้องการปุ่มสองปุ่มให้ใช้ปุ่ม A และ B บนตัว micro:bit ช่วย
